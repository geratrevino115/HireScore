🎯 Flujo end-to-end

Vacante → guía de entrevista → candidato (CV) → pipeline. Sigue el orden de FLUJO.md.
1 Crear o elegir vacante
Una vacante guarda título, descripción y requisitos. El backend luego los usa para extraer skills estructurados, calcular score y generar la guía de entrevista.
→ Lista todas las vacantes en BD (GET /vacancies/).
→ Sube PDF/DOCX con la descripción de la vacante. El LLM extrae título, descripción y requisitos (POST /vacancies/extraer-desde-archivo). Devuelve un borrador editable; nada se guarda todavía.
📝 Borrador extraído — revisa y edita
→ No tienes la JD. Llenas puesto, seniority, stack… y el LLM propone una vacante completa (POST /vacancies/generar). También devuelve borrador editable; nada se guarda todavía.
📝 Borrador IA — revisa y edita
→ Llenas el formulario tú mismo (POST /vacancies/).

📋 Guía de entrevista (opcional pero recomendado por FLUJO.md)
Genera preguntas + criterios de evaluación a partir de los requisitos (POST /vacancies/{id}/guia-entrevista). Se reutiliza en la entrevista del candidato.
2 Agregar candidato — subir CV
Una sola llamada (POST /analyses/procesar) ejecuta todo el pipeline:
  1. 📄 Guarda el CV (PDF/DOCX) en data/cv_data/
  2. 🧠 Extrae datos estructurados con el LLM (nombre, email, skills, experiencia, educación)
  3. 👤 Dedupe: si no pasas candidato_id, busca por el email del CV; si no existe, crea uno
  4. 📐 Calcula score vs requisitos con pesos (default o custom) + sentimiento si hay audio
  5. 📋 Crea Aplicacion en etapa nueva (pivote candidato↔vacante)
  6. 💾 Persiste Analisis con desglose y registra costo LLM

3 Resultado + pipeline
Score del candidato + estado del pipeline de la vacante. Puedes mover candidatos entre etapas (PATCH /aplicaciones/{id}/etapa) para simular el kanban.
